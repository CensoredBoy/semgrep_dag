## Введение

### Почему безопасность агентов критична

AI агенты представляют качественно новый уровень риска по сравнению с обычными LLM-приложениями:

| Аспект | Обычное LLM приложение | AI Агент |
|--------|------------------------|----------|
| Действия | Только генерация текста | Выполнение реальных действий |
| Автономность | Нет | Самостоятельное принятие решений |
| Доступ к ресурсам | Ограничен | Файловая система, API, БД, интернет |
| Цепочка действий | Одноразовый запрос | Многошаговое выполнение |
| Последствия ошибок | Неверный текст | Реальный ущерб системам |

### Описание слоёв защиты

| Слой | Назначение | Компоненты |
|------|------------|------------|
| **Input Guardrails** | Первичная фильтрация входящих запросов | Валидация схемы, детекция инъекций, rate limiting, контентная фильтрация |
| **Policy Engine** | Применение бизнес-правил и политик безопасности | NeMo Guardrails, YAML-правила, динамические политики |
| **Agent Core** | Ядро агента с защищённым reasoning | Изолированный LLM, контролируемое планирование, защищённая память |
| **Tool Execution** | Безопасное выполнение инструментов | Реестр инструментов, проверка разрешений, sandbox, аудит |
| **Output Guardrails** | Фильтрация исходящих данных | Удаление PII, проверка фактов, фильтрация токсичности |

## Заключение

### Ключевые выводы

1. **AI агенты требуют специализированного подхода к безопасности** — стандартные практики для LLM недостаточны, так как агенты выполняют реальные действия.

2. **Defense in Depth критичен** — множественные слои guardrails (input, policy, tool, output) обеспечивают защиту при отказе одного из компонентов.

3. **Secure SDLC должен быть адаптирован** — каждая фаза разработки требует специфических артефактов безопасности для AI агентов.

4. **Continuous testing необходим** — регулярный red teaming и автоматизированное adversarial testing должны быть частью процесса.

5. **Мониторинг и аудит — основа реагирования** — без детального логирования невозможно обнаружить и расследовать инциденты.

### Матрица приоритетов внедрения

| Приоритет | Мера | Сложность | Влияние |
|-----------|------|-----------|---------|
| **P0** | Input Guardrails (injection detection) | Средняя | Критичное |
| **P0** | Tool sandboxing | Высокая | Критичное |
| **P0** | Audit logging | Низкая | Высокое |
| **P1** | Policy Engine (NeMo Guardrails) | Средняя | Высокое |
| **P1** | Output Guardrails (PII, toxicity) | Средняя | Высокое |
| **P1** | RBAC для tools | Средняя | Высокое |
| **P2** | Adversarial testing в CI/CD | Средняя | Среднее |
| **P2** | Memory protection | Средняя | Среднее |
| **P3** | Constitutional AI approach | Высокая | Среднее |
