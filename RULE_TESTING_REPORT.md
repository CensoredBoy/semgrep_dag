## Файл правил: `airflow-bash-unsafe`

### Правило: `airflow-bash-unsafe-jinja-conf`
**Описание:** ОПАСНО: BashOperator использует dag_run.conf в bash_command без валидации. Это может привести к RCE.
**Тестовый файл:** `test_airflow-bash-unsafe-jinja-conf.py`
**✅ Сработало:** Найдено 1 срабатывание(й)
- Строка 11: 

**Код в тесте (строки 12-15):**
```python
    task_id='bash_unsafe',
    bash_command="{{ dag_run.conf['cmd'] }}",  # ОПАСНО! RCE через HTTP
    dag=dag,
)
```

**Почему сработало:**
Правило обнаружило использование небезопасных Jinja шаблонов в BashOperator. Команда формируется из пользовательских данных (dag_run.conf/params/xcom), что может привести к Command Injection. Злоумышленник может передать через HTTP запрос команду, которая будет выполнена на сервере.

## Файл правил: `airflow-rce-eval-exec`

### Правило: `airflow-eval-in-python-callable`
**Описание:** КРИТИЧНО: Использование eval() в функции, которая может быть использована в PythonOperator. Это может привести к Remote Code Execution.
**Тестовый файл:** `test_airflow-eval-in-python-callable.py`
**✅ Сработало:** Найдено 1 срабатывание(й)
- Строка 11: 

**Код в тесте (строки 12-15):**
```python
    cmd = context['dag_run'].conf.get('cmd', 'print("hello")')
    result = eval(cmd)  # ОПАСНО!
    return result

```

**Почему сработало:**
Правило обнаружило использование eval()/exec() в коде. Это критическая уязвимость Remote Code Execution (RCE), так как позволяет выполнить произвольный Python код. Если данные для eval/exec приходят из внешних источников (dag_run.conf, params, xcom), злоумышленник может выполнить любой код.
